Code structure
Assets		all game content, game data, fonts, sound and graphics
BuildX		helper scripts to automate code templates for managers components + game screens
Engine		helper scripts to register manager components + boot strap game

Game
Inputs		code for keyboard and mouse input detection
Managers	each manager component is responsible for a particular game system or service. 
Objects		game data models to represent configuration, questions and text elements
Screens		each game screen represents particular state in game managed by screen manager 
Static		globally loaded game assets, colors definitions, constants, enums and global text

Tests		most manager components were written and tested in isolation using TDD style

Simpsons Trivia
Main game entry point that runs the [in]finite game loop until shutdown:
first thing you may notice that is different in video game development in the game loop

A game loop is the repeating cycle that keeps a game running:
Input → Update game state → Render graphics → Repeat

It exists so the game can continuously respond to the player, update what's happening, and 
display the result many times per second - measured as FPS - Frames Per Second


AnGame.py
Builds game infrastructure and acts as an intermediary between the game bootstrap and the service registry which delegates game init, load, update and draw game loop methods to actual game implementation code.


MyGame.py
Delegates game init, load, update + draw game static methods to actual management implementation code.
