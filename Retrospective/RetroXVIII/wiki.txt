<br />
The future of the Software Engineer: one that integrates AI coding agents with human judgement and taste.
<br /><br />
<b>History</b><br />
<!-- --> 
Back in <a href="https://www.freethink.com/robots-ai/github-copilot">2023</a>, big tech companies predicted AI coding <a href="https://en.wikipedia.org/wiki/AI_agent">agents</a> would write more of our code, eventually all of it.  A coding agent is more than autocomplete:  it reads a codebase, plans changes, edits files, runs tests and iterates on its own.  Companies adopted these tools and many treated them as a way to replace engineers.  
<br /><br />
Now in <a href="https://medium.com/data-science-collective/coding-in-2026-doesnt-look-anything-like-2019-530d50120aef?sk=8cb665c4b3be862a923e7f4582f93c55">2026</a>, the reality looks more complicated. Agents write plenty of code, but code isn't the hard part of software engineering.  The hard parts are <a href="https://martinfowler.com/bliki/AgenticProgramming.html">judgement</a> and taste: knowing what to build, trade-offs to accept + what will break at 3am, and what will be unmaintainable in three years.  Teams that removed experienced people found those gaps quickly:  experience is worth more now than it has ever been.  

<br /><br />
<!-- -->
<br />

<b>Seniors</b><br />
<!-- -->
Senior Software Engineers are <a href="https://blog.jetbrains.com/research/2026/08/ai-coding-agent-adoption-2026">embracing</a> AI coding agents rather than resisting them.  They'll use tools like GitHub Copilot every day, but they don't let an agent write code unsupervised.  They give the coding agent context, constraints and acceptance criteria, then review its output and test and verify everything before it ships.  The agent gives them speed; their experience supplies rigour that makes the result robust + reliable.  
<br /><br />  
Seniors are also well placed to extend this to colleagues working in adjacent engineering disciplines, such as Machine Learning and Deep Learning.  These engineers have strong expertise in mathematics, algorithms and modelling, while their experience in software engineering practices may differ.  Seniors' guidance plus agents can help bridge the gap, supporting better structure, error handling, testing and engineering practices, much as a thoughtful code review would.

<br /><br />
<!-- -->
<br />

<b>Juniors</b><br />
<!-- -->
The biggest open question is the next generation.  If companies let AI write more code then junior engineers lose the <a href="https://arxiv.org/abs/2602.00496">traditional</a> path to becoming senior engineers: years of writing, breaking + fixing real systems with experienced colleagues.  That process of working through difficult problems, debugging failures and learning from production incidents is how engineering judgement and taste are developed.
<br /><br />
Agents can help here too, if we use them as tutors rather than shortcuts.  Juniors can ask an agent to explain why code is designed the way it is.  They can have it challenge their solutions in the way a patient reviewer would, and use it to practise debugging and reading unfamiliar code.  Senior engineers still need to mentor, review and set the standards.  The aim should be to make sure the next generation of senior engineers still earns its judgement and taste, whoever or whatever happens to type the code.
<br /><br />
<!-- -->
<br />

<b>Strategy</b><br />
Looking ahead to 2027, one strategy is to <a href="https://dora.dev/insights/balancing-ai-tensions">adopt</a> AI agents deliberately: setting clear guardrails with agent instruction files, coding standards, mandatory code review and automated testing, so every AI-generating change meets the same bar as human-written code. 
<br /><br />
Next, start with low-risk, high-value work such as tests, refactoring, documentation + boilerplate then widen the agents' scope only as <a href="https://survey.stackoverflow.co/2025/ai">trust</a> is measured and earned.  Pair Senior Engineers with ML and DL Engineers and mentor Juniors using agents as a shared teaching tool.
<br /><br />
Finally, reward what matters: quality, reliability and delivery outcomes and not the volume of code produced. Engineers who understand the craft will lead this transition.  They will treat AI as a powerful <a href="https://research.google/pubs/towards-ai-as-a-collaborative-partner-a-taxonomy-of-ai-agent-behavior-in-software-engineering">collaborator</a> that still needs direction, verification and always good judgement and taste.
