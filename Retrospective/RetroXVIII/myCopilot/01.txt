# The Future of Software Engineering: AI Writes the Code, Engineers Own the Craft

Back in 2023, the direction of travel seemed obvious. Big technology companies predicted that AI coding agents would write ever more of our code, eventually perhaps all of it. A coding agent is more than autocomplete: it can read a codebase, plan changes, edit files, run tests and iterate on its own. Companies adopted these tools quickly, and there was understandable excitement about what they might mean for software engineering. Some saw them primarily as a way to reduce the need for engineers. Three years on, the reality looks more complicated. Agents can write enormous amounts of code, but code was never the hardest part of software engineering. The difficult parts are judgement and taste: knowing what to build, understanding the trade-offs, recognising what might break at 3am, and seeing when a seemingly elegant solution will become unmaintainable three years from now. The more code AI can produce, the more important those skills become.

Experienced senior engineers are therefore embracing AI coding agents rather than resisting them. They use tools such as GitHub Copilot every day, but they don't simply hand over responsibility. They give the agent context, constraints and clear acceptance criteria, then review its output and test and verify everything before it ships. The agent provides speed; the engineer provides the rigour that makes the result robust and reliable. This is less like replacing an engineer and more like giving an experienced engineer a very fast, highly capable junior collaborator who never gets tired of writing boilerplate. There is an opportunity here beyond traditional software teams too. Machine Learning and Deep Learning engineers can be exceptionally strong in mathematics, algorithms and modelling while having less experience with some of the practices that come from years of professional software engineering. A senior engineer working alongside them can use agents to help turn that technical expertise into production-quality software: better structure, clearer error handling, stronger tests, better observability and more maintainable designs. In that sense, the agent can amplify the effect of a good code review rather than eliminate the need for one.

The biggest open question is what happens to the next generation of engineers. If companies allow AI to write most of the code, juniors could lose some of the traditional apprenticeship through which I learned software engineering: years of writing, breaking and fixing real systems alongside more experienced people. Those frustrating bugs, awkward refactorings and production incidents were not wasted time. They were how judgement was developed. I don't think the answer is to keep AI away from junior engineers. It is to use it differently. Agents can be excellent tutors if we treat them as tutors rather than shortcuts. A junior can ask an agent to explain why a piece of code is structured in a particular way, challenge a proposed solution, practise debugging, explore an unfamiliar codebase or simulate the questions a thoughtful reviewer might ask. But the senior engineer still has an important role: setting standards, asking the difficult questions, reviewing the work and making sure the junior understands the reasoning rather than simply accepting the answer. The goal should be to make sure that the next generation still earns its judgement and taste, whoever or whatever happens to type the code.

Looking towards 2027, I think the strategy should be to adopt AI agents deliberately, not simply quickly. First, teams need clear guardrails: agent instruction files, coding standards, mandatory code review, automated testing and well-defined boundaries around what agents are allowed to change. AI-generated code should meet exactly the same engineering bar as human-written code. Second, teams should start with low-risk, high-value work such as tests, refactoring, documentation and boilerplate, and widen the agents' scope as trust is earned and measured. Third, organisations should invest in people. Senior engineers can pair with ML and Deep Learning engineers, while mentoring juniors and using agents as a shared teaching tool. Finally, teams should measure what actually matters: quality, reliability, security, maintainability and delivery outcomes, rather than the volume of code produced. The metric should not be “how much code did the agent write?” but “did we build the right thing, and does it work reliably?” Engineers who understand the craft will be central to this transition. The future of software engineering isn't humans versus AI. It is engineers who know what good software looks like, working with increasingly capable machines that still need direction, verification and good judgement.
