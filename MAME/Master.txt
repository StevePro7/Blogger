A1.
What that developer is doing with the original 1987 arcade game Shinobi is a fascinating example of reverse engineering an old arcade game. The good news is that you can extract and inspect a large part of the original graphics, sprites, and audio using tools available today. You don't necessarily need to disassemble the entire game or write your own extraction software.

The important distinction is that shinobi.zip is not normally a single game file containing everything in an easily readable format. A MAME ROM set generally contains several ROM images, each holding a different part of the arcade hardware's data: program code, graphics data, sound-program code, and possibly samples or other data.

For a Mega Drive/Genesis port, the developer then has to go beyond extraction: they must understand how the arcade hardware arranges its graphics, composes its backgrounds, plays its music, and runs its game logic, and reproduce those features on different hardware.

Let's break down how you can investigate each part yourself.
1. First, identify what is inside shinobi.zip

MAME's documentation explains that arcade ROM sets contain separate images of the chips on the original board, rather than one unified game-data file. 
GitHub

For Shinobi, the ROMs fall into several broad categories:

    Main CPU program ROMs: the 68000 game code, which controls gameplay, enemies, level progression, and graphics setup.

    Graphics ROMs: encoded pixel data for backgrounds, characters, enemies, objects, and other visual elements.

    Sound program ROMs: code that controls the sound hardware and responds to requests from the main game.

    Audio data and samples: music-related data, sound-effect data, or sampled audio, depending on the sound device.

    Other ROMs and keys: data used by particular board revisions, protection systems, or other hardware functions.

The exact files depend on which Shinobi ROM set you have. MAME lists multiple versions, including unprotected System 16A and protected System 16A/System 16B sets.

3. How to extract complete level backgrounds

This is the part where extracting raw tiles and extracting a complete level are very different jobs.

A level background in Shinobi is not necessarily stored as one big image. Sega System 16 hardware uses tile layers and a separate sprite layer. The game builds the visible scene from many small graphical elements, with scrolling and palette selection.

To reconstruct a level, you need to recover several things:

    Tile graphics: the small images that form scenery, buildings, walls, ground, and other background elements.

    Tilemap data: the arrangement of those tiles, including their positions and attributes.

    Palette data: the colours assigned to the tile pixels.

    Scrolling and layer information: how the game moves and combines the background layers during play.

The tile graphics may be relatively straightforward to decode, but the tilemap and its attributes can be harder to identify because they are often assembled or updated by the game code.
The practical extraction workflow

    Use MAME's viewer to identify the background graphics and palettes.

    Capture screenshots of each stage as a visual reference.

    Examine the Shinobi driver in MAME's source code to learn how its graphics regions and tile layers are decoded.

    If you want actual reusable background maps, investigate the game's tilemap memory and level data rather than simply stitching together screenshots.

    Export the reconstructed background as PNGs or convert it into your own tile-and-map format.

Step 5 — Identify the exact background ROMs from MAME's source code

Inspect the ROM declarations in that section. In particular, look for these kinds of declarations:
cpp

These are examples of the declaration syntax, not the actual Shinobi ROM filenames or sizes.

Look for region descriptions containing terms such as tiles, sprites, or gfx. The exact names depend on the driver.
